**P1 封面｜20s**
各位老师好，我是网络工程 2203 班杨佳星。今天汇报的题目是《基于容器化部署的云文件管理系统设计与实现》，指导老师王晓梅老师。下面用 7 分钟左右汇报。

**P2 目录｜15s**
汇报分四部分：背景与目标、系统设计与容器化部署、核心功能实现、运行展示与总结。

**P3 研究背景｜30s**
传统部署有四类痛点：环境耦合、依赖版本、初始化脚本、目录权限。容器化把这些一次性收敛：一键启动、版本钉死、数据持久、跨机一致。课题关注的不是"能不能做"，而是"能否稳定部署、运行、演示、验证"。

**P4 目标与技术路线｜35s**
八个功能模块：登录、上传、目录、预览、分享、回收站、统计、容器化部署。技术栈横向贯通：前端 Vue3 + Element Plus + Vite；后端 Spring Boot 3.2.2 + MyBatis-Plus；安全 JWT + BCrypt；数据 MySQL 8 + Redis 7；部署 Nginx + Docker Compose；文件处理 Aspose / PDFBox / JAVE。边界：不做多租户、不做完整 RBAC、不做配额。

**P5 总体架构｜40s**
五层结构：表现层 Vue3 SPA；业务层 Spring Boot REST；数据层 MySQL 存元数据 + Redis 存临时状态；部署层 Nginx 做静态资源和反向代理；文件处理层 Aspose / PDFBox / JAVE 封装多格式预览。前后端解耦，扩展灵活。

**P6 容器化部署｜45s**（核心，慢一点）
四容器：用户 → Nginx → Backend → MySQL/Redis，对外只暴露 Nginx。`docker compose up -d --build` 后七步：① 命令下发 → ② 拉/构镜像 → ③ 建网络与卷 → ④ MySQL/Redis 起 → ⑤ 健康检查 → ⑥ Backend 启动加补丁 → ⑦ Nginx 入口就绪。换台机器只要装 Docker，一行命令就能起。

**P7 文件上传与管理｜45s**
三个关键点：① **物理 + 元数据双写**——文件落 `/files`，元数据写 lfs_file 表，用 MD5 关联；② **MD5 秒传**——前端先算 MD5，命中则只挂元数据，磁盘只占一份；③ **软删除**——删除只打回收站标记，超期再异步清理。

**P8 JWT 鉴权与隔离｜50s**（核心，慢一点）
五步链路：① 登录 HMAC 签 token → ② Header 带回 → ③ 拦截器验签查过期，非法 401 → ④ 注入 userId 到上下文 → ⑤ SQL 强制 `WHERE user_id = ?`。三个好处：服务端无状态、签名防伪造、隔离在后端强制不靠前端。现场 admin / demo 两个账号互不可见。

**P9 运行界面①｜20s**
左：登录页；右：文件空间主界面。Web 应用基础状态。

**P10 运行界面②｜20s**
左：分享码 + 有效期；右：预览成功。匿名分享可达，反代下预览稳定。

**P11 运行界面③｜25s**
左：`docker ps` 四容器全 Up；右：24 个自动化用例全过。部署到业务闭环稳定。

**P12 总结与展望｜45s**
完成：① 完整业务闭环；② 容器化一键部署；③ 预览链路修复（签名 + 路径归一化）；④ 双用户隔离。不足：① 权限模型简单，未引入 RBAC；② 存储为本地目录，未接对象存储；③ 监控基础，缺日志聚合与指标采集。
