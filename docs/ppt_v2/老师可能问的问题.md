## 一、关于"为什么用容器化部署"

### Q1. 为什么不直接在服务器上手工部署？非要上 Docker？
**3 秒抓手**：因为这个课题关心的不是"能不能跑出来"，而是**任何一台机器都能稳定地跑起来**。

**展开回答**：
1. 传统部署**和机器强耦合**——JDK 版本、MySQL 版本、Redis 端口、上传目录权限，每换一台机器就要重新踩坑；
2. 容器化把**依赖版本钉死在镜像里**，一条 `docker compose up -d --build` 就能拉起 nginx / backend / mysql / redis 四个服务；
3. 数据通过 **volumes 外挂**，重启容器不丢数据，配合 `healthcheck` 还能让后端等 MySQL 真正就绪后再启动，避免启动顺序错乱。

**追问兜底**：如果老师追问"为什么是 Compose 不是 K8s"——答：本课题是单机部署场景，4 个容器，Compose 足够；K8s 适合多节点编排，超出本课题边界。

---

### Q2. docker-compose.yml 里的 `depends_on + condition: service_healthy` 是什么作用？
**3 秒抓手**：让 backend 等 MySQL **健康检查通过**之后再启动。

**展开回答**：
- 普通的 `depends_on` 只保证容器**启动顺序**，不保证 MySQL 进程**真正就绪**；
- `condition: service_healthy` 配合 MySQL 容器内的 `healthcheck`（执行 `mysqladmin ping`），让 backend 在 MySQL 真正可连接后才启动；
- 这样能避免后端启动瞬间 JDBC 连接失败导致服务挂掉。

---

### Q3. PPT 第 6 页那个"兼容补丁"是干什么的？
**3 秒抓手**：后端启动时**自动补齐数据库结构**，让旧库也能跑起来。

**展开回答**：
- 项目早期 `lfs_file` 表里没有 `user_id` 字段，是后期为了用户隔离才加上去的；
- 直接交付别人的环境如果还是旧库，手工改表很麻烦；
- 所以在后端启动逻辑里加了**幂等补丁**：检测字段不存在就 `ALTER TABLE` 添加，同时建立唯一索引、初始化 demo 账号；
- 已经存在则跳过——保证任何旧库都能无缝升级到当前结构。

## 二、关于"JWT 与用户隔离"（第 8 页 ★ 工程亮点）

### Q4. 为什么用 JWT 不用 Session？
**3 秒抓手**：JWT **无状态**，便于水平扩展；Session 需要服务端共享存储。

**展开回答**：
1. JWT 是 **客户端持有 token、服务端不存状态**，多个后端实例之间不需要同步会话；
2. Token 用 **HMAC 签名**，密钥仅在服务端，任何篡改都会在 verify 阶段被拒绝；
3. 即便后续要做集群部署，也不必引入 Redis 共享 Session 这种额外依赖。

**追问兜底**：如果问"JWT 不能主动失效怎么办"——答：可在 Redis 里维护**短期黑名单**或缩短 token 有效期（本系统设的是 14400 秒 = 4 小时）。

---

### Q5. 用户隔离怎么实现的？我登录之后怎么就只看得到自己的文件？
**3 秒抓手**：每条业务 SQL 都被强制追加 `WHERE user_id = ?` 条件。

**展开回答**：
1. 用户登录成功后，JwtConfig 把 **userId 写进 token 的 claims**；
2. 拦截器在每次请求都 `parseToken` 解出 userId，丢到 `CurrentUserService`（ThreadLocal）；
3. MyBatis Mapper 中所有查询 / 更新 / 删除 SQL 都**强制带 user_id 条件**，绝不依赖前端传入；
4. 即便有人绕过前端、伪造请求 ID 想看别人文件，SQL 层面也直接 0 行返回——做到**后端强制隔离**。

**追问兜底**：如果问"那分享链接怎么让别人看到我的文件"——答：分享场景是**显式授权**，单独走 `lfs_file_share` 表 + 分享码 + 有效期校验，不走 user_id 隔离。

---

### Q6. JWT 的签名密钥泄露了怎么办？
**3 秒抓手**：密钥通过**环境变量**注入，不进代码仓库。

**展开回答**：
- 项目里 `appSecret` 不写在源码里，而是从 Spring Boot 的 `application.yml` 读取，部署时通过 docker compose 的 `environment` 注入；
- 一旦怀疑泄露，**只需修改环境变量并重启 backend 容器**，所有现存 token 立刻失效；
- 生产环境建议接入密钥管理服务（如 Vault），但这是本课题边界外的扩展项。

## 三、关于"文件上传 / 预览 / 分享"

### Q7. MD5 秒传的实现细节是什么？大文件不就慢了？
**3 秒抓手**：前端**分块计算 MD5** 后先问后端，命中就跳过上传。

**展开回答**：
1. 前端用 `spark-md5` 库**对文件分块流式计算 hash**，不会一次性读完整个文件占内存；
2. 计算完成后先调 `/api/file/check`，后端查 `lfs_file` 表里有没有相同 MD5 的物理文件；
3. 命中：直接给当前用户写一条**指向已有物理文件的元数据**，秒返回成功；
4. 未命中：才走真正的 multipart 上传流程；
5. 这样**多人重复上传同一文件**只占一份物理空间，省存储。

---

### Q8. 预览链路是怎么稳定下来的？老师我看你 PPT 上提到"预览链路修复"。
**3 秒抓手**：预览链接加了 **secret + expire 双签名 + 路径归一化**。

**展开回答**：
- 早期预览直接拼 `/api/preview?path=xxx`，存在两个问题：① 路径可能被构造越权（如 `../../etc/passwd`），② 链接可被无限期重放；
- 修复方案：
  - **路径归一化**：把传入路径做 `Paths.get(...).normalize()`，并校验是否在合法根目录下，越界直接 403；
  - **签名机制**：链接里带 `expire` 时间戳和 HMAC 签名 `sig`，后端校验签名正确且未过期才放行；
- 这样既防越权也防长期滥用。

### Q9. Office 文档预览是怎么实现的？为什么我能在浏览器里看 Word？
**3 秒抓手**：后端用 **Aspose 把 Office 转成 PDF**，前端按 PDF 渲染。

**展开回答**：
- 浏览器原生不能显示 .doc / .xls / .ppt；
- 后端引入 **Aspose-Words / Aspose-Cells / Aspose-Slides**，在用户点预览时把 Office 文档实时转换成 PDF；
- PDF 通过 PDFBox 校验有效性后，作为流式响应回传前端；
- 视频则用 **JAVE2** 做必要的转码兼容；
- 前端使用 PDF.js 渲染，避免下载到本地才能看。

**追问兜底**：如果问"Aspose 是付费组件吗"——答：是商业库，本课题用的是评估版本；生产环境可替换为 LibreOffice headless + jodconverter 这种开源方案。

### Q16. JWT 的三段式 `Header.Payload.Signature` 具体是怎么生成和校验的？
**3 秒抓手**：前两段是 Base64 编码的 JSON，第三段是用密钥对前两段做 HMAC-SHA256 得到的签名。

**展开回答**：
1. **Header**：声明算法类型，如 `{"alg":"HS256","typ":"JWT"}`，做 Base64URL 编码；
2. **Payload**：放业务声明（claims），比如 `userId`、`exp`（过期时间）、`iat`（签发时间），同样 Base64URL 编码；
3. **Signature**：把前两段拼成 `Header编码.Payload编码`，用 secret 做 HMAC-SHA256 哈希；
4. 校验时服务端把收到的前两段**重新算一次签名**，跟传过来的第三段比对——任何字符被改过，签名都会对不上，直接拒绝。

**追问兜底**：HS256 是对称加密（单密钥），如果换成 RS256 就是非对称（私钥签名 / 公钥验证），适合多服务之间分发。

---

### Q17. HMAC 和普通哈希（如直接 SHA256）有什么区别？为什么签名一定要用 HMAC？
**3 秒抓手**：普通哈希谁都能算，HMAC **必须有 secret 才能算出正确结果**。

**展开回答**：
1. 普通 SHA256：输入 → 输出固定，**没有密钥参与**，攻击者拿到输入也能伪造一致的哈希；
2. HMAC：在哈希过程里**混入服务端独有的 secret**，攻击者没有 secret 就算不出正确签名；
3. 这就是为什么 JWT 篡改 Payload 之后**没法重算出合法签名**——他没有 secret。

**比喻**：普通哈希像"任何人都会盖的普通章"，HMAC 像"刻着独有花纹的私章，仿不出来"。

---

### Q18. BCrypt 加密密码相比直接 MD5 / SHA256 好在哪里？
**3 秒抓手**：BCrypt **天生带盐 + 慢**，专门用来抗暴力破解。

**展开回答**：
1. **自带盐值（salt）**：每次加密同一个密码都会生成不同密文，**防止彩虹表攻击**；
2. **可调慢速**：通过 `cost` 因子（默认 10）控制运算轮数，每加一就让破解时间翻倍；普通哈希算一次只要纳秒级，BCrypt 故意做到几十毫秒；
3. **用法**：注册时 `BCryptPasswordEncoder.encode(明文密码)` 存数据库；登录时 `matches(明文, 密文)` 校验，**永远不存明文**。

**追问兜底**：现在更新的方案有 Argon2、Scrypt，原理类似但更抗 GPU 暴力破解；本课题选 BCrypt 是因为 Spring Security 默认支持、生态成熟。

### Q19. Docker 的镜像分层是怎么回事？为什么每次 build 都说"使用缓存"？
**3 秒抓手**：每条 Dockerfile 指令生成**一层只读层**，没变就直接复用缓存。

**展开回答**：
1. 镜像由**多层只读层 + 顶部一层可写层**组成（联合文件系统 OverlayFS）；
2. Dockerfile 里每一行 `RUN` / `COPY` / `ADD` 都会生成一个新层，并且**带哈希指纹**；
3. 重新 build 时，Docker 从上往下比对：**指纹一致就用缓存**，第一次变化的那行开始重建后面所有层；
4. 这就是为什么大家把"不常变的依赖安装"放在前面、"经常改的源码 COPY"放在后面——能最大化命中缓存。

**对应实践**：项目 Dockerfile 里 `COPY pom.xml` 放在 `COPY src` 前面，就是这个套路，让 Maven 依赖只在 pom 改变时才重新下载。

### Q20. 容器之间怎么互相访问？docker-compose.yml 里的 `networks` 起什么作用？
**3 秒抓手**：Compose 会建一个**自定义网桥**，容器之间用**服务名当 DNS** 互访。

**展开回答**：
1. Compose 启动时默认建一个 bridge 网络，所有 service 都加进去；
2. 在这个网络里，容器**用 service 名字就能解析到对方 IP**，比如 backend 连 MySQL 直接写 `jdbc:mysql://mysql:3306/...`，这里的 `mysql` 是服务名而不是 IP；
3. 不在同一网络的容器**默认互相不可见**，这就是为什么 Nginx 和 backend 要显式声明在同一个 networks 下；
4. 对外暴露则通过 `ports: 80:80` 做宿主机端口映射，**只有 Nginx 暴露**，MySQL/Redis/Backend 都不直接对外。

### Q21. Redis 在你这个系统里到底存了什么？为什么不直接用 MySQL？
**3 秒抓手**：Redis 存**短期高频读写的临时状态**，比如分享码、token 黑名单。

**展开回答**：
1. **分享码缓存**：分享链接里的 code → fileId 映射放 Redis，带 TTL（过期时间）；过期 Redis 自动清理，不用写定时任务；
2. **登录态辅助**：可以做 token 黑名单（主动失效）；
3. **为什么不用 MySQL**：MySQL 写盘，QPS 上不去；过期数据要自己写定时任务清；Redis 是内存数据库，**纳秒级读写 + 自动 TTL** 天然适合这种场景；
4. **不丢数据**：Redis 也开了 AOF 持久化，重启不丢核心 key。

**追问兜底**：如果问"为什么不用本地缓存（Caffeine）"——答：本地缓存多实例之间不一致；Redis 是**集中式**的，将来扩到多 backend 实例还能继续用。

### Q22. MyBatis-Plus 比原生 MyBatis 多了什么？你用了它哪些特性？
**3 秒抓手**：MP 在 MyBatis 之上加了**通用 CRUD + 条件构造器**，少写大量样板 SQL。

**展开回答**：
1. **BaseMapper**：继承之后自动获得 `insert / updateById / selectById / selectList` 等基础方法，单表 80% 的 SQL 不用手写；
2. **LambdaQueryWrapper**：用 lambda 表达式拼条件，比如 `.eq(LfsFile::getUserId, userId).eq(LfsFile::getDel, 0)`，**编译期就能查字段名错误**；
3. **逻辑删除**：实体加 `@TableLogic` 注解，delete 自动变 `UPDATE SET del=1`，配合软删除场景；
4. **分页插件**：`Page<T>` 一行代码搞定分页 SQL；
5. 复杂多表 join 还是回到原生 XML 写——MP 不是替代，是辅助。

### Q23. Vue 3 的响应式原理是什么？比 Vue 2 好在哪里？
**3 秒抓手**：Vue 3 用 **Proxy 代理整个对象**，能监听 Vue 2 监听不到的属性变化。

**展开回答**：
1. Vue 2 用 `Object.defineProperty` 给每个属性单独装拦截器，**新增属性、删除属性、数组索引修改**都监听不到，要靠 `Vue.set` 这种 hack；
2. Vue 3 用 ES6 的 `Proxy`，**整个对象被代理**，任何字段变化（增删改）都能自动捕获；
3. 配合 `ref` / `reactive` API，加上 Composition API 把逻辑组织得更清晰；
4. 编译时还做了 **静态提升 + Patch flag**，运行时只 diff 真正会变的节点，性能比 Vue 2 高一截。

---

### Q24. Vite 和 Webpack 比有什么本质区别？为什么开发体验快这么多？
**3 秒抓手**：Vite **不打包**，直接让浏览器走 ES Module 按需加载。

**展开回答**：
1. **Webpack 开发模式**：要先把所有模块**全量打包成 bundle**，项目越大启动越慢；
2. **Vite 开发模式**：启动只做**依赖预构建**（用 esbuild，毫秒级），源码不打包；浏览器请求 `/src/main.js` 时 Vite 现场转换并返回，**按需编译**；
3. esbuild 是 Go 写的，比 webpack 的 JS 实现快 10-100 倍；
4. **生产构建**仍然走 Rollup 全量打包，保证体积优化；
5. 所以本课题选 Vite，主要是开发期改一行代码、热更新几乎瞬时反映。

---

### Q25. Spring Boot 的拦截器（Interceptor）和过滤器（Filter）有什么区别？你 JWT 校验用的哪个？
**3 秒抓手**：Filter 是 **Servlet 规范**层面的，Interceptor 是 **Spring MVC** 层面的；JWT 用的是 Interceptor。

**展开回答**：
1. **执行顺序**：请求进来先过 Filter，再到 DispatcherServlet，再过 Interceptor，最后到 Controller；
2. **作用域**：Filter 能拦到所有请求（包括静态资源）；Interceptor 只拦 Spring MVC 处理的请求；
3. **能力**：Interceptor 能拿到 `HandlerMethod`，可以判断目标方法上有没有特定注解（比如 `@Login`、`@SkipAuth`），**做更精细的策略控制**；
4. JWT 校验用 Interceptor，方便对 `/api/login`、`/api/share/visit` 这类不需要登录的接口做白名单。

---

### Q26. 为什么 Nginx 配置里要把 `/api/` 反向代理到 backend，不能直接前端调 backend 端口吗？
**3 秒抓手**：直接调会**跨域**，而且暴露 backend 端口不安全。

**展开回答**：
1. 浏览器同源策略：协议 + 域名 + 端口 三者完全一致才不算跨域；前端跑在 80 端口，backend 在 8080 就跨域了；
2. 走 Nginx 反代之后，**前端和 API 看起来在同一个域同一个端口**，浏览器认为是同源，没有 CORS 问题；
3. backend 容器**不对外暴露端口**，只在内部网络可见，攻击面更小；
4. Nginx 还顺便做了 gzip 压缩、静态资源缓存、SPA fallback（任意路径回退到 `index.html`）等。

---

### Q27. 为什么 MD5 用来去重可以，用来存密码就不行？
**3 秒抓手**：去重只看**碰撞概率**，存密码要看**抗暴力破解能力**。

**展开回答**：
1. 文件去重场景：两个不同文件 MD5 撞上的概率约 1 / 2^128，**实际工程上完全可忽略**；
2. 密码存储场景：MD5 计算极快，攻击者用 GPU 一秒能算几十亿次，**配合彩虹表常见密码秒破**；
3. 所以同一个算法在不同场景下，**安全要求维度不一样**；
4. 本系统密码用 BCrypt（自带盐 + 慢），文件指纹用 MD5（够快够稳），是**按场景选工具**，不是技术倒退。

---

### Q28. 为什么文件上传要用 `multipart/form-data`，而不是直接 POST JSON？
**3 秒抓手**：JSON 只能传文本，multipart 能在一次请求里**混传二进制 + 文本字段**。

**展开回答**：
1. JSON 是纯文本格式，二进制必须 Base64 编码，**体积膨胀 33%**；
2. `multipart/form-data` 用边界字符串（boundary）切分多段，每段可以是文件、可以是字段，**原样传输不膨胀**；
3. Spring Boot 用 `@RequestParam("file") MultipartFile file` 直接接收，框架自动处理边界解析；
4. 配合 `Content-Length` 让 Nginx 和 backend 都能提前感知请求大小，做大小限制和进度显示。

---

### Q29. 你说预览链接做了路径归一化，具体怎么防 `../../etc/passwd` 这种攻击？
**3 秒抓手**：先 `Paths.get(path).normalize()`，再校验**归一化后的路径必须以合法根目录开头**。

**展开回答**：
1. **归一化**：`Paths.get("/files/a/../../etc/passwd").normalize()` 会算出 `/etc/passwd`，把 `../` 这种相对跳跃都展开；
2. **根目录前缀校验**：归一化后的路径如果**不以 `/files/` 开头**，直接 403；
3. 还要做**符号链接检查**：`toRealPath()` 解开软链后再次校验，防止有人在合法目录下创建指向系统目录的软链；
4. 三道防线叠加，路径穿越基本封死。

---

### Q30. 如果同时有 100 个人上传同一个大文件，你这个系统会怎么样？
**3 秒抓手**：因为有 **MD5 秒传**，第 2~100 个人**几乎瞬时完成**，只占一份磁盘。

**展开回答**：
1. 第 1 个人：正常分块上传，落物理文件 + 写元数据；
2. 第 2~100 个人：前端先算 MD5 → check 接口命中 → 后端**只写一条新元数据**指向已有物理文件，几乎零网络流量；
3. 真正的瓶颈在 check 接口对 MD5 字段的查询，所以 `lfs_file.md5` 字段我加了**唯一索引**，查询是 O(log n)；
4. 进一步优化可以把"MD5 → 物理路径"映射放进 Redis，连 DB 查询都省掉。

### Q31. 你说的"自动化测试 24 用例全过"，是单元测试还是集成测试？区别是什么？
**3 秒抓手**：是**集成测试**，整个 Spring Boot 容器拉起来打真实 HTTP 接口。

**展开回答**：
1. **单元测试**：只测一个类、一个方法，依赖用 mock 替代，跑得快但**测不到联调问题**；
2. **集成测试**：用 `@SpringBootTest` 把整个应用启动起来（含数据库、Redis、拦截器），用 `MockMvc` 或 `TestRestTemplate` 打真实接口；
3. 我这 24 个用例都是集成测试，覆盖**真实链路**：JWT 拦截 → Controller → Service → Mapper → MySQL 全跑通；
4. 每个用例独立、互不依赖（用 `@Transactional` + 回滚保证数据干净）。

## 七、必懂技术原理小卡片（精简版，背 8 张就够）

> 这部分不是"考试范围"，而是当老师追问"那个 XX 的原理是什么"时，你能用**一句话比喻 + 一句关键事实**接住。  
> 每张卡片只要求你理解到能复述比喻和关键事实即可，**不必背具体代码**。

---

### 🃏 卡片 1：Docker 容器到底是什么？
**比喻**：像一个**带操作系统环境的"罐头"**，把代码 + JDK + 系统库一起封进去。  
**关键事实**：容器共享宿主机内核，但文件系统、网络、进程相互隔离；比虚拟机轻量（几十 MB vs 几 GB），秒级启动。  
**对应 PPT**：第 3 页右侧"容器化方案"、第 5 页"部署与代理层"。  
**最坏情况兜底**：如果细节问太深，回答"我把它当作可移植的应用包来使用，更深的内核 namespace / cgroup 不是本课题研究边界"。

---

### 🃏 卡片 2：Docker Compose 解决了什么？
**比喻**：单个 Dockerfile 是"做一道菜的食谱"，docker-compose.yml 是"**一桌菜的总菜单+上菜顺序**"。  
**关键事实**：用 YAML 描述多容器拓扑（服务、网络、数据卷、依赖关系），一条 `up -d` 启动整桌菜。  
**对应 PPT**：第 6 页（核心亮点）。  
**关键词**：services、depends_on、healthcheck、volumes、networks。

---

### 🃏 卡片 3：`healthcheck` + `depends_on: service_healthy` 的意义
**比喻**：默认 `depends_on` 只保证容器**"亮灯了"**，不保证里面的程序**"开门营业"**。`service_healthy` 让它等到真正能服务再放行。  
**关键事实**：MySQL 容器内每隔几秒执行 `mysqladmin ping`，连续成功后状态变 healthy；backend 才会启动。  
**为什么重要**：避免后端启动瞬间连不上 DB、JDBC 报错挂掉，是部署稳定性的关键一笔。

---

### 🃏 卡片 4：JWT 到底"无状态"在哪？
**比喻**：传统 Session 像**俱乐部门口的会员名单**，每次进门要查名单（服务端存储）；JWT 像**带防伪印章的会员卡**，门口看一眼印章对不对就放行（服务端不存任何东西）。  
**关键事实**：JWT 由 `Header.Payload.Signature` 三段 Base64 组成；签名是 `HMAC-SHA256(Header+Payload, secret)`，密钥仅服务端知道；所以**篡改 Payload 必然导致签名不匹配**，被验签直接拒绝。  
**对应 PPT**：第 8 页 步骤 ① ② ③。  
**最常见追问**：JWT 怎么主动失效？答：**Redis 黑名单 + 短有效期**（本系统 4 小时）。

---

### 🃏 卡片 5：用户隔离为什么要在 SQL 层而不是前端做？
**比喻**：前端校验像"**门口写着请勿入内的牌子**"，后端 SQL 校验像"**真正上锁的门**"。  
**关键事实**：所有 Mapper 的 SQL 都强制带 `WHERE user_id = ?`，userId 来源是 token 解析出来的，**绝不接受前端传入**。  
**为什么重要**：哪怕攻击者绕过前端、自己拼请求带别人的文件 ID，后端 SQL 也直接 0 行返回。这是"信任边界"思想：**只信令牌，不信前端**。

---

### 🃏 卡片 6：MD5 秒传 / 内容寻址
**比喻**：像快递的"**条形码扫一下就知道有没有同款**"——同样的文件无论谁上传都得到同一个 MD5。  
**关键事实**：上传前前端先用 `spark-md5` **分块流式**计算文件 hash，调 `/api/file/check` 询问后端是否已有同 MD5 物理文件。命中就只写一条新元数据指向旧文件，**不再传输实际字节**。  
**为什么不会撞 hash**：MD5 在密码学上已不安全，但用于"去重"够用；本课题不是反篡改场景。  
**对应 PPT**：第 7 页中卡片"MD5 秒传机制"。

---

### 🃏 卡片 7：预览链接的"签名 + 过期"是怎么回事？
**比喻**：像演唱会门票上的"**入场时间 + 防伪二维码**"——过了时间或票面被改都进不去。  
**关键事实**：链接里带 `expire`（过期时间戳）+ `sig`（HMAC 签名）。后端先校验时间没过、再用 secret 算一遍 sig 比对，两道都通过才放行预览。  
**额外一道防线**：路径要做 `Paths.get(...).normalize()` 规范化，禁止 `../` 越界访问宿主机其他目录。  
**对应 PPT**：第 12 页"预览链路修复"成果项。

---

### 🃏 卡片 8：Nginx 反向代理在这里的角色
**比喻**：Nginx 是**大楼前台**，把外面的访客（80 端口）按"找哪个部门"分别引到 Vue 静态资源或 backend API。  
**关键事实**：① 把 `/api/*` 转给 backend 容器内部 8080 端口；② 把其他路径（前端路由）回退到 `index.html` 让 Vue Router 接管；③ 同时托管 SPA 静态文件，浏览器只看到一个域一个端口，**没有跨域问题**。  
**为什么排在第 7 位启动**：它是用户的"**入口**"，必须等 backend 起来后才有意义对外开放。
