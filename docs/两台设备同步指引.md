# 两台设备（Mac ↔ Windows）同步操作指引

> 目标：让 GitHub 上始终是「最新的论文工作件 + 可用且适配的项目代码」。
> 角色分工（重要）：
> - **论文 / docs**：以 **Mac** 为准（Mac 上是最新终稿，Windows 上的论文是旧的，禁止用 Windows 覆盖论文）。
> - **项目代码 project/**：以 **Windows** 为准（Windows 上是真实 Docker 环境、毕设实际跑通的版本，可能含让它跑通的改动）。

## 三、给 Windows 电脑智能体的提示词（直接复制粘贴给它）

把下面整段发给 Windows 上的智能体：

```
我有一台 Mac 和这台 Windows，同一个毕业设计项目。我已经在 Mac 上整理好并推送到 GitHub：
仓库地址：https://github.com/RexaNax/<仓库名>（请替换为实际地址）。

分工原则（必须严格遵守）：
1. 论文和 docs/ 目录：以 GitHub（Mac 版）为准。这台 Windows 上的论文是旧的，绝对不要用本机论文覆盖 GitHub 上的论文。
2. 项目代码 project/：以这台 Windows 为准。因为真实 Docker 环境和毕设实际跑通都在这台 Windows 上，本机 project/ 里可能有让它跑通的改动（配置、路径、依赖版本、compose、nginx 等）。

请按以下步骤执行：

第一步：克隆 GitHub 仓库到一个临时目录（不要直接覆盖我本机现有项目），例如：
  git clone https://github.com/RexaNax/<仓库名>.git C:\yjxbishe_github

第二步：只对比 project/ 目录，找出本机 project/ 与 GitHub 版 project/ 的差异：
  - 用 git diff 或逐文件对比，列出：哪些文件本机有改动、改了什么、为什么（尤其是 docker-compose.yml、nginx 配置、application.yml/properties、Dockerfile、数据库连接、卷路径、端口、依赖版本）。
  - 重点标出"让 Docker 在本机跑通"相关的改动。
  - 输出一份差异清单给我看，先不要动手合并。

第三步：等我确认后，把本机 project/ 中"真实跑通所需"的改动合并进 GitHub 仓库副本的 project/：
  - 把 C:\yjxbishe_github 设为工作仓库；
  - 把本机跑通版 project/ 的有效改动覆盖/合并到 C:\yjxbishe_github\project/；
  - 不要动 C:\yjxbishe_github\docs/（论文以 Mac 为准）。

第四步：在 C:\yjxbishe_github 里提交并推回 GitHub：
  cd C:\yjxbishe_github
  git add project/
  git commit -m "fix: 同步 Windows 真实 Docker 环境下跑通的项目改动"
  git push

注意：
- 不要提交 node_modules、target、dist、本机绝对路径密钥等；遵守仓库已有的 .gitignore。
- 如果 docker-compose.yml 里有本机绝对路径（如 C:\... 卷映射），请改成相对路径或在 README 里注明需按环境调整，不要把仅你本机可用的硬编码路径推上去。
- 合并完成后，请告诉我 project/ 里相比 GitHub 版具体改了哪些文件、关键差异是什么，方便我在 Mac 上同步认知。
```

## 五、如何判断两台设备差异 / 怎么过滤旧内容

你担心"Windows 上论文是旧的"，过滤方法就是**分目录定责**：

| 目录 | 权威方 | 同步动作 |
|---|---|---|
| `project/` | Windows（真实跑通） | Windows 改动 → push → Mac pull |
| `docs/`（论文、正式提交、图表、ppt） | Mac（最新终稿） | Mac 为准，Windows 不回写 docs |

只要 Windows 智能体严格"只动 project/、不动 docs/"，Windows 上的旧论文就不会污染 GitHub。Git 本身按文件粒度对比，`git diff` / `git status` 会精确列出每个文件的差异，不存在"整目录盲目覆盖"。

## 六、长期协作建议

- 以后两台设备都从 GitHub 这个仓库为单一事实源（single source of truth）。
- 每次开工前先 `git pull`，收工前 `git commit && git push`。
- 论文只在 Mac 改、代码只在 Windows 改，能最大限度避免冲突。
- 若某天需要在 Windows 改论文 / Mac 改代码，先 pull 最新，改完立即 push，并在 commit message 注明改了什么。
