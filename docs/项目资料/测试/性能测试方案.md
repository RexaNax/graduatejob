## 二、测试准备

### 2.1 安装 JMeter

1. 下载：https://jmeter.apache.org/download_jmeter.cgi
2. 解压到 `C:\jmeter`
3. 运行 `C:\jmeter\bin\jmeter.bat`

### 2.2 获取测试 Token

```bash
# 登录获取 token（用于后续接口测试）
curl -X POST http://localhost/api/user/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}'

# 返回示例：{"code":0,"data":{"token":"xxx..."},"msg":"success"}
# 记录 token 值用于后续测试
```

## 三、测试场景

### 3.1 场景一：登录接口压测

**目的**：测试认证服务的并发处理能力

| 参数 | 值 |
|------|---|
| 接口 | POST /api/user/login |
| 并发数 | 10 → 50 → 100 |
| 持续时间 | 60秒/轮 |
| 请求体 | `{"username":"admin","password":"123456"}` |

**JMeter 配置**：
1. 添加 Thread Group：线程数=50，循环=永远，持续时间=60s
2. 添加 HTTP Request：
   - 协议: http
   - 服务器: localhost
   - 端口: 80
   - 路径: /api/user/login
   - 方法: POST
   - Body: `{"username":"admin","password":"123456"}`
3. 添加 HTTP Header Manager：Content-Type: application/json
4. 添加 Summary Report 和 Aggregate Report

### 3.2 场景二：文件列表查询压测

**目的**：测试数据库查询性能

| 参数 | 值 |
|------|---|
| 接口 | GET /api/file/list?parentId=0&page=1&pageSize=20 |
| 并发数 | 10 → 50 → 100 |
| 持续时间 | 60秒/轮 |
| 认证 | Header: token=xxx |

### 3.3 场景三：文件上传压测

**目的**：测试上传服务的处理能力

| 参数 | 值 |
|------|---|
| 接口 | POST /api/file/upload |
| 并发数 | 5 → 10 → 20 |
| 测试文件 | 1MB 文本文件 |
| 认证 | Header: token=xxx |

**注意**：上传测试并发不宜过高，避免磁盘 IO 成为瓶颈

### 3.4 场景四：文件下载压测

**目的**：测试静态文件服务能力（Nginx）

| 参数 | 值 |
|------|---|
| 接口 | GET /api/file/download/{fileId} |
| 并发数 | 10 → 50 → 100 |
| 持续时间 | 60秒/轮 |

## 五、部署对比测试

### 5.1 传统部署 vs 容器部署

| 对比项 | 传统部署 | Docker 部署 |
|--------|----------|-------------|
| **环境准备时间** | 安装 JDK + MySQL + Redis + Nginx（约 __分钟） | `docker compose up -d`（约 __分钟） |
| **首次启动时间** | 分别启动各服务（约 __分钟） | 一键启动（约 __分钟） |
| **重启恢复时间** | 手动重启各服务（约 __分钟） | `docker compose restart`（约 __秒） |
| **配置修改** | 修改多个配置文件 | 修改 docker-compose.yml 环境变量 |
| **环境隔离** | 与系统共享环境 | 完全隔离 |
| **迁移难度** | 需重新安装配置 | 复制文件 + `docker compose up` |
