### 2026-01-15 部署对账记录（Win11 vs Mac）

> 目的：把今天为了让 `C:\yjxbishe` 在 Win11 + Docker 下跑通而做的**仓库内文件变更**记录下来，方便你明天与 Mac 开发环境逐条对账。

---

### 一、今天遇到的关键问题（背景）
- **MySQL 端口冲突**：宿主机 `3307` 被本机 `mysqld.exe` 占用，导致 `docker compose up` 报端口绑定失败。
- **访问 `localhost` 返回 403**：Nginx 挂载的 `../frontend/dist` 为空（无 `index.html`），触发 `directory index is forbidden`。
- **后端容器反复重启**：镜像里缺少 `app.jar`，日志为 `Error: Unable to access jarfile app.jar`。

---

### 二、文件级变更清单（只包含仓库内真实修改）

#### 1) `project/deploy/docker-compose.yml`
- **变更**：MySQL 端口映射从 `"3307:3306"` 改为 **`"3308:3306"`**。
- **原因**：Win11 上本机 `mysqld.exe` 占用 `3307`，Docker 无法绑定该端口。
- **对 Mac 的建议**：如果 Mac 上 `3307` 没冲突，可改回 `3307:3306`；否则保持 `3308`。

#### 2) `project/deploy/nginx/nginx.conf`
- **变更**：增加 Docker DNS resolver，避免 `nginx` 在后端短暂不可解析时启动失败。
  - 增加：`resolver 127.0.0.11 valid=10s ipv6=off;` 与 `resolver_timeout 5s;`
- **变更**：让 upstream 支持运行时解析，避免出现 `host not found in upstream "backend:8919"`。
  - upstream 增加共享内存：`zone backend 64k;`
  - server 行改为：`server backend:8919 resolve;`
- **对 Mac 的建议**：这项改动在 Mac Docker 环境同样有益（尤其是 `backend` 重启/延迟启动时）。

#### 3) `project/frontend/package.json`
- **变更**：从 `dependencies` 中移除 `canvas`。
- **原因**：在 Win11 + Node v22 环境下，`canvas` 安装会走 `node-pre-gyp` 下载预编译包但匹配不到（404），继而导致依赖安装失败、`vite` 不可用、`dist` 无法构建。
- **影响评估**：项目中使用的是浏览器原生 `<canvas>`（例如 `src/views/preview/AudioPreview.vue`），并未发现代码里引用 Node 原生 `canvas` 包，因此移除不影响前端运行。
- **对 Mac 的建议**：如果你 Mac 侧依赖链确实需要 `canvas`（例如做 SSR/服务端渲染或 node 侧图片处理），建议改为：
  - **固定 Node LTS（18/20）** + 补齐 `canvas` 的编译依赖；
  - 或继续保持移除 `canvas`（推荐，当前项目看起来不需要）。

#### 4) `project/backend/pom.xml`
- **变更**：打包类型从 `war` 改为 **`jar`**。
- **变更**：移除 `maven-war-plugin`，改为增加 **`spring-boot-maven-plugin`** 并启用 `repackage`。
- **原因**：Docker 运行时需要可执行的 Spring Boot fat-jar（`app.jar`）。此前 `war` + 无 repackage 导致镜像内没有可运行的 `app.jar`，容器启动失败。
- **对 Mac 的建议**：这项改动属于“让后端可以直接 `java -jar` 运行”的通用修复，建议 Mac 侧也保持一致。

### 三、非仓库变更（仅供参考，不建议纳入对账结论）
- **本机层面**：发现 `mysqld.exe` 占用 `3307`（所以我们改了 docker 映射端口）。
- **构建产物**：`project/frontend/dist` 是构建输出目录（一般不进 Git）。
- **临时清理**：为解决依赖问题，执行过删除 `node_modules`、删除 `package-lock.json` 后重装（属于工作区操作，不一定需要在 Mac 复现）。

### 四、建议的对账/验证步骤（Mac 上照做即可）
- **前端**：
  - `cd project/frontend`
  - `npm install`
  - `npm run build`（确认生成 `dist/index.html`）
- **后端（容器）**：
  - `cd project/deploy`
  - `docker compose up -d --build`
  - `docker compose ps`（确认 `backend/mysql/redis/nginx` 均为 Up）
- **访问验证**：
  - 浏览器打开 `http://localhost`（预期 200）
  - 可选：`curl http://localhost/health`（预期 200/OK）
